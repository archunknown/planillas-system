2. FORMULARIO TRABAJADOR — FRICCIÓN DE TIPOS z.input<> / z.coerce.date()
====================================================================================

PROBLEMA DETECTADO (igual que Lote 2, resuelto sin cast):
  CrearTrabajadorSchema tiene fechaNacimiento: z.coerce.date()
  z.input<typeof CrearTrabajadorSchema>['fechaNacimiento'] → unknown (Zod v4)
  Si se usa CrearTrabajadorSchema directamente como form schema,
  zodResolver valida empresaId también (field no registrado en el form) → falla.

SOLUCIÓN APLICADA:
  1. Se creó CrearFormSchema = CrearTrabajadorSchema.omit({ empresaId: true })
     empresaId es prop del componente, no campo del formulario
  2. useForm<z.input<typeof CrearFormSchema>>({ resolver: zodResolver(CrearFormSchema) })
     → ningún cast necesario para el form
  3. En onSubmit: { ...data, empresaId } as z.input<typeof CrearTrabajadorSchema>
     → cast justificado: el action llama schema.parse() internamente

  Para EditarForm: useForm<z.input<typeof ActualizarTrabajadorSchema>>
  defaultValues.fechaNacimiento = trabajador.fechaNacimiento.toISOString().split('T')[0]
  TypeScript: string → unknown, sin problema

CAMPO SEXO: Nativo <select> en vez del @base-ui Select
  Razón: sexo tiene solo 2 opciones (M/F), el select nativo funciona en
  jsdom sin mock adicional, y simplifica los tests (TF4 usa fireEvent.change).
